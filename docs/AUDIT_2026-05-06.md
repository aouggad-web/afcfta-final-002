# Audit Report — 2026-05-06

## Scope
- Reviewed authentication and API-key administration flow.
- Ran a targeted static scan for sensitive patterns and risky code usage.

## Findings

### 1) High: Authentication bypass when database is unset
`require_auth` currently returns a public-tier context when `_db` is `None` instead of failing closed. This can silently disable API-key enforcement in misconfigured environments.

- Location: `backend/auth.py`
- Risk: accidental production exposure if database wiring is skipped.
- Recommendation: return `503 Service Unavailable` with explicit message until DB is configured.

### 2) Medium: Admin key listing includes inactive keys without filtering
`list_keys` returns all API keys regardless of `active` status. This is not a direct exploit, but can increase operational confusion and expose excessive metadata to admins.

- Location: `backend/routes/admin_keys.py`
- Recommendation: default to `active: true` and add optional query flag for historical/inactive listing.

### 3) Medium: No input constraints on key metadata
`CreateKeyRequest` does not validate `name` or `owner` lengths/format. Oversized or malformed values can degrade observability and log hygiene.

- Location: `backend/routes/admin_keys.py`
- Recommendation: apply minimum/maximum lengths and basic normalization.
